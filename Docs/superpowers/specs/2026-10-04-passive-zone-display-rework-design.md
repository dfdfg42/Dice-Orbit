# 패시브 구역 표시 리워크 설계 — "구역 테"

- 날짜: 2026-10-04
- 상태: 구현됨 (§6) — 승인 (사용자 요청 — "패시브 구역 표시를 카드에 다 브래킷으로 하는데, 몬스터와 구역 표시가 명확해졌으니 리워크해야 할 것 같다")
- 브랜치: `feature/passive-zone-display-20261004` (← main)
- 선행: `2026-09-25-monster-zone-intent-reskin-design.md` (구역 플레이트), `Docs/battle_visual_language.md`

## 1. 지금의 표시

캐릭터를 조회(호버·핀)하면 `PassiveRangeIndicator`가 패시브 범위 **타일마다 네 모서리에 ㄱ자 브래킷**을 그린다.

| 문제 | 내용 |
|---|---|
| 단위가 안 맞는다 | 범위 패시브 3종(방진·협공·마력 회로)은 2026-08-28 개편으로 전부 **구역 단위**가 됐는데, 표시는 타일 단위다. 구역 하나에 브래킷 20개, 마력 회로 3구역이면 60개 |
| 구역 표시와 따로 논다 | 구역은 이제 잉크 플레이트로 한 덩어리로 보인다. 브래킷은 그 위에 흩어진 점처럼 보여 "이 구역"이라는 뜻이 안 읽힌다 |
| 얼마나 걸려 있는지 모른다 | 세 패시브 모두 "같은 구역 아군 수" 등에 따라 값이 변하는데, 지금 몇 %인지는 어디에도 없다 |
| 꺼진 상태가 안 보인다 | 아군이 없어 효과가 0이어도 브래킷은 똑같이 켜진다 |

## 2. 목표 / 비목표

**목표**
- 패시브가 걸린 구역을 **한 덩어리**로 읽게 한다 — 구역당 도형 하나.
- 조회하는 순간 **지금 값**이 보인다 (정보 패널 패시브 제목 옆 "받는 피해 -20%").
- 효과가 꺼져 있으면(조건 미충족) 흐리게 보여 구분된다.
- 데이터 계약을 타일 목록에서 **구역 번호**로 바꾼다 — 패시브가 구역→타일로 풀어 주던 변환을 없앤다.

**비목표**
- 패시브 규칙·수치는 바꾸지 않는다.
- 조회 중에만 표시하는 규칙은 유지한다 (상시 표시 없음, 타게팅 중 숨김).
- 몬스터 쪽 표시(위협 타일 외곽선·리프트·플레이트 색)는 건드리지 않는다.
- 공용 모디파이어(합류 전술·독립 행동 등 구역 조건 모디파이어)의 표시는 이번 범위 밖 — 같은 인터페이스를 구현하면 붙도록 열어 두기만 한다.

## 3. 형태

조회한 캐릭터의 구역 패시브마다:

1. **구역 테두리** — 구역 부채꼴(플레이트 안쪽 가장자리 ~ 타일 바깥)을 통째로 감싸는 둥근 모서리 폐곡선 하나. 타일 위·유닛 아래에 그린다.
   두 겹 선: 짙은 남색 잉크 밑선 + 밝은 하늘색 심선 — 어떤 플레이트 색 위에서도 읽힌다.
   구역 경계는 타일 사이를 지나므로 선이 타일을 가로지르지 않는다.
2. **구역 밝힘** — 그 구역의 플레이트를 흰색으로 살짝 밝힌다(색상은 유지 — 주인 몬스터 색 의미를 해치지 않는다).
3. **지금 효과** — 정보 패널의 패시브 제목 옆(액티브의 주사위 조건이 놓이는 자리)에 한 줄.
   - 방진: `받는 피해 -20%` / 꺼짐 `같은 구역 아군 없음`
   - 협공: `주는 피해 +60%` / 꺼짐 `같은 구역 아군 없음`
   - 마력 회로: `3구역 연결` / 꺼짐 `자기 구역만`
   걸려 있으면 굵은 잉크, 꺼져 있으면 흐린 회색. 월드에 글자를 띄우지 않는 이유는 §6.
4. **꺼진 상태** — 테두리 알파를 낮추고 밝힘을 끈다.

조회 중 아군이 움직이거나 죽으면 매 프레임 다시 계산해 바로 따라간다. 나타날 때 0.15초 페이드인.

시각 언어 사전의 "패시브 영향 범위 = 타일 모서리 ㄱ자 브래킷" 항목을 "패시브 구역 = 구역 테두리 + 밝힘"으로 바꾼다. 선 채널(둘레 외곽선)은 몬스터 위협 타일에도 쓰지만 그쪽은 **타일 단위·몬스터 정체성 색**, 이쪽은 **구역 단위·하늘색 두 겹 선**이라 겹치지 않는다. 숨쉬기 펄스(스킬 타게팅 전용)는 쓰지 않는다.

## 4. 구조

```
Combat/Passive/IPassiveZoneProvider.cs   구역 패시브 계약 — CollectPassiveZones(List<int>) + GetPassiveZoneStatus()
                                         (IPassiveRangeProvider 삭제 — 구현체 3종 전부 구역 단위라 타일 계약이 남을 이유가 없다)
Visuals/ZoneSectorShape.cs               순수 기하 — 둥근 모서리 부채꼴 폐곡선 점열 (자가 테스트)
Visuals/PassiveZoneIndicator.cs          조회 캐릭터의 구역 패시브 → 테두리·밝힘 (PassiveRangeIndicator 삭제)
UI/InfoPanel/{BattleInfoData,UnitInfoBuilder,BattleInfoPanelUI}   PassiveInfoData.LiveEffect/LiveActive → 패시브 제목 옆 메타
Visuals/ZonePlateRenderer.cs             TryGetPlate(zone, out SpriteRenderer) 공개 — 밝힘·정렬 기준
Editor/PassiveZoneSelfTests.cs
```

- 패시브 3종: `GetRangeTiles()` 삭제 → `CollectPassiveZones` + `GetPassiveZoneStatus`. 지금 효과 한 줄은 순수 함수(`FormatZoneStatus`)로 빼 자가 테스트한다. 방진의 감쇄율 계산은 `OnAttack`과 표시가 같은 함수(`ReductionPercent`)를 쓴다.
- 테두리 기하: 구역 각도 범위(`GetZoneAngularRangeDeg`)를 양쪽 경계에서 **일정 거리**(각도가 아니라 길이)만큼 안으로 들인다 — 반지름 R에서 각도 여유 = asin(d/R). 바깥 반지름 = 그 구역 타일 모서리 중 가장 먼 것 + 여유.
- 정렬: 플레이트와 같은 정렬 레이어, 플레이트 +10 (유닛 −40) — 발밑 마커(−1)·유닛보다 뒤, 플레이트보다 앞.
- **폴백 없음**: 기하 인자가 말이 안 되면(안쪽 반지름 ≤ 들임 등) 예외. 궤도·플레이트가 아직 준비 전이면 그리지 않고 다음 프레임을 기다린다(플레이트 렌더러와 같은 규칙).

## 5. 검증

- `PassiveZoneSelfTests`: 부채꼴 점열이 반지름·경계 들임 안에 있는지, 폐곡선 간격, 잘못된 인자 예외, 지금 효과 글자(켜짐/꺼짐/상한).
- Play: 전사·마법사·도적을 서로 다른 구역/같은 구역에 두고 조회 캡처 — 테두리가 타일을 가로지르지 않는지, 패널의 지금 효과 값, 꺼진 상태, 조회 중 실시간 갱신, 콘솔 에러 0.

## 6. 구현 결과 (2026-10-04)

- 설계와 달라진 점 — **월드 꼬리표를 뺐다.** 처음엔 구역 안쪽 가장자리에 크림 이름표("방진 · 받는 피해 -20%")를 띄웠는데, 그 자리는 아래쪽 구역 몬스터의 이름·HP 바가 올라오는 곳이라 겹쳤다(바깥 호 쪽은 캐릭터 머리 위 UI·주사위 트레이와 겹친다). 구역 위에는 글자를 얹을 빈자리가 없다 → 월드는 "어디"(테두리·밝힘)만, "얼마나"는 정보 패널 패시브 제목 옆으로 옮겼다. 조회 중에는 패널이 항상 같이 떠 있고 주기적으로 다시 그려져 실시간 갱신도 그대로 된다.
- 기본값: 안쪽 반지름 2.95, 바깥 = 구역 타일 최외곽 모서리 + 0.4, 경계 들임 0.3, 모서리 굴림 0.9, 심선 0.2 / 밑선 0.46, 꺼짐 알파 ×0.4, 밝힘 0.22, 페이드 0.15초. 색은 `UiSkin.Secondary`(하늘) + `UiSkin.Ink`.
- 검증
  - `PassiveZoneSelfTests` 8건 통과.
  - Play: ① 셋이 서로 다른 구역 — 전사·도적은 흐린 테두리 1개 + "같은 구역 아군 없음", 마법사는 밝은 테두리 3개 + "3구역 연결" ② 전사 조회 중 마법사가 전사 구역으로 이동 — 테두리가 밝아지고 패널이 "받는 피해 -10%"로 바뀜 ③ 몬스터 조회 — 구역 테두리 0개 ④ 조회 해제 — 전부 사라짐. 콘솔 에러 0.
  - 타게팅 중 숨김은 코드 경로만 유지(이전과 같은 `SkillTargetSelector.IsSelectingTarget` 판정) — Play로 따로 캡처하지는 않았다.
