# 행동 예고 설계 — "누르기 전에 다 보인다"

- 날짜: 2026-10-04
- 상태: 구현됨 (§7) — 승인 (사용자 요청 — "캐릭터가 이동 예상만 되는데, 예상 공격·데미지도 뜨고 필요한 걸 미리 알도록 전반적으로 수정")
- 브랜치: `feature/action-forecast-20261004` (← `feature/passive-zone-display-20261004`)

## 1. 지금

캐릭터와 주사위를 고른 뒤 **[이동] 버튼에 마우스를 올려야** 경로(체브론)와 도착 타일이 보인다. 그게 전부다.

| 모르는 채로 누르는 것 | 실제로는 |
|---|---|
| 누구를 때리는가 | 도착 구역의 주인 / 마력 회로 / 양옆 구역 등 캐릭터·단계마다 다르다 |
| 얼마나 들어가는가 | 공격력 × 단계 배율 × 패시브·모디파이어·상태·타일 — 계산은 파이프라인 안에만 있다 |
| 강화 공격이 나가는가, 콤보가 끊기는가 | 주사위 눈이 조건을 못 맞추면 콤보가 0으로 돌아가고 기본공격이 나간다 |
| 가는 길에 무엇을 밟는가 | 지뢰·점액·시약·꿀·불꽃… 통과만 해도 발동한다 |
| 거기 서면 맞는가 | 도착 타일이 몬스터 공격 범위인지 |

## 2. 목표 / 비목표

**목표**
- 주사위를 **고르는 순간**(그리고 다른 주사위에 **마우스를 올리는 순간**) 그 주사위로 벌어질 일을 전부 예고한다 — 버튼 호버를 기다리지 않는다.
- 예고 수치는 실제 실행과 **같은 코드**에서 나온다. 예고용 계산식을 따로 두지 않는다.
- 예고는 상태를 바꾸지 않는다 (콤보·상태 소모·알림·RNG 없음).

**비목표**
- 전투 규칙·수치는 바꾸지 않는다.
- 타격이 적중할 때 붙는 부가 효과(중독·감전 부여 등)가 **같은 행동의 뒤 타격**에 주는 영향은 반영하지 않는다 — 예고는 "지금 상태 기준"이다.
- 회피(확률)는 수치에 넣지 않고 "회피 N%"로만 알린다.
- 몬스터 공격의 예상 피해 수치는 이번 범위 밖 — 범위 안인지만 알린다.

## 3. 무엇을 예고하는가

| 항목 | 내용 |
|---|---|
| 이동 | 경로 체브론 + 도착 타일 (기존 `MovePathPreview`, 이제 주사위 선택 즉시) |
| 공격 종류 | `2단계 [지진파]` / `기본 공격` / `공격 없음 (사거리에 몬스터 없음)` / `이번 턴엔 이미 공격함` |
| 대상별 피해 | 대상마다 체력 손실 합계, 다단이면 `9×2`, 방어도가 깎이면 표시, `처치` 또는 `남은 체력` |
| 콤보 | `다음 3단계` / `콤보 완성` / `콤보 끊김 — 주사위 눈 4 이상 필요` / `콤보 초기화 (표적 없음)` |
| 경로 | 지나가며 발동하는 타일: `지뢰 피해 5`, `촉매 획득`, `점액: 이동 -1` … (촉매처럼 이번 공격에 영향을 주는 것은 피해 수치에도 반영) |
| 턴 종료 | 도착 타일에서 턴을 마치면: `속박`, `불꽃 피해 20`, `체력 5% 회복` … |
| 위험 | 도착 타일이 몬스터 공격 범위면 `위험: 초록 슬라임 [박치기]` |

## 4. 형태

- **월드**
  - 도착 타일 → 각 대상 몬스터로 **조준 포물선**(기존 조준선 형태, 이동 경로와 같은 노랑 — §7).
  - 대상 몬스터 몸 위에 **예상 피해 숫자**: `-18` / `-20 처치` / `방어도 -5` (실제 피해 팝업과 같은 글꼴).
- **예고 카드** — [이동] 버튼 위(오른쪽 맞춤 — 오른쪽에는 정보 패널이 있다). 공격 종류 → 대상 줄 → 콤보 → 경로/턴 종료/위험 순. 나쁜 소식은 빨강, 좋은 소식은 초록, 나머지는 잉크.
- 표시 시점: 캐릭터 패널이 열려 있고 주사위가 선택됨 → 계속 표시(0.25초마다 다시 계산). 다른 주사위에 마우스를 올리면 그 주사위로 잠깐 바뀌고, 떼면 선택한 주사위로 돌아온다. 이동 실행·취소·패널 닫힘 시 사라진다.

## 5. 구조

```
Combat/Forecast/ActionForecast.cs       예고 데이터 (종류·대상별 결과·콤보 변화·노트·위험)
Combat/Forecast/ActionForecaster.cs     계산 — 아래 '같은 코드' 조각들을 예측 스코프 안에서 호출
Combat/Forecast/ActionForecastText.cs   카드·꼬리표 문구 (순수 — 자가 테스트)
Tile/TileForecast.cs                    타일 속성이 예고에 적는 창구 (노트 + 부여할 상태)
Visuals/ActionForecastView.cs           조준선·꼬리표·카드 (런타임 생성, UiSkin)
```

**같은 코드에서 나오게 하는 장치**
- `AutoAttackSystem.PlanAttack(character, diceValue, passedZones)` → `AttackPlan` — 강화/기본/표적 없음 판정과 표적 수집을 실행 루틴(`ResolveRoutine`)과 예고가 **같이 쓴다**. 판정은 상태를 바꾸지 않고, 콤보 초기화·통지는 실행 루틴에만 남는다.
- `OrbitManager.BuildMovePath` — 이동 경로 계산 한 곳 (이동 루틴·예고·지나간 구역 수집이 공유).
- `UnitStats.ResolveDamage` — 방어도 흡수·무적 처리 순수 함수. `TakeDamage`와 예고가 공유.
- `CombatPipeline.SimulateCalculation(context, extraReactors)` — 기존 시뮬레이션 경로. 경로에서 얻을 상태(촉매 등)를 가상 리액터로 끼워 넣는다.
- `Character.PretendAt(tile)` — using 블록 동안 `CurrentTile`이 도착 타일을 가리킨다. 구역 판정·패시브(방진·협공·마력 회로)·타일 속성(예리함 등)·위치 모디파이어가 전부 `CurrentTile`을 읽으므로 한 번에 "도착했다고 치고" 계산된다. 트랜스폼·타일 점유 표시는 건드리지 않는다. 동기 구간에서만 쓴다(코루틴 양보 금지).
- `AttackActionScope.Simulate(source, info)` — 주사위 눈·콤보 단계·구역 넘음 정보를 읽는 모디파이어·1회성 상태(촉매·고양·감전)가 예고에서도 같은 조건으로 판정된다. 끝나면 이전 스코프를 그대로 되돌린다.
- `TileAttribute.ForecastTraverse / ForecastEndTurn(character, TileForecast)` — 타일 속성이 "지나가면/턴을 마치면 벌어질 일"을 스스로 적는다. 통과 시 사라지는 속성은 `MarkConsumed()`로 알려 턴 종료 예고에서 빠진다.

**폴백 없음**: 궤도·파이프라인이 없으면 예고를 만들지 않는다(null) — 틀린 숫자를 보여 주지 않는다. 강화 공격이 `ComboActiveSkill`이 아닌 설계 위반은 실행 루틴이 기존처럼 에러로 알린다.

## 6. 검증

- `ActionForecastSelfTests`: 피해 적용 순수 함수(방어도·무적·다단 누적·처치), 문구(종류·콤보·대상 줄·노트 병합), 타일 예고 노트.

## 7. 구현 결과 (2026-10-04)

- 시스템 문서: `Docs/action_forecast_system.md`.
- 설계와 달라진 점
  - **조준선은 초록이 아니라 노랑.** 초록 구역 플레이트 위에서 초록 점선이 묻혔다. 이동 경로(체브론)와 같은 노랑으로 맞춰 "저기로 가서 → 이걸 친다"가 한 줄로 이어지게 했다.
  - **예상 피해는 발밑 꼬리표가 아니라 몸 위 숫자.** 실제 피해 팝업과 같은 글꼴·외곽선을 써서 "이 숫자가 뜰 것"으로 읽힌다 (`FloatingLabelPopup.ApplyPopupStyle` 공유).
  - 기존 [이동] 버튼 호버 프리뷰(`ShowMovePreview`)와 쓰이지 않던 경로 헬퍼는 삭제 — 경로 표시는 `ActionForecastView`가 맡는다.
- 검증
  - `ActionForecastSelfTests` 10건 통과 (기존 PassiveZone·HitFeel·RewardFlow 자가 테스트도 통과).
  - Play 대조 — 예고를 만든 뒤 같은 주사위로 실제 이동·공격을 실행해 비교: **11건 전부 일치** (대상별 체력 손실·도착 타일·콤보 단계). 전사 1·2·3단계(다중 대상), 기본공격, 콤보 끊김, 도적 다단 3×2, 표적 없는 구역(콤보 초기화), 마법사 1·2단계, 마법사 콤보 끊김.
  - 예고를 두 번 연달아 만들어도 결과가 같고 콤보 단계가 변하지 않음을 매 건 확인.
  - UI 흐름 — 주사위 선택 즉시 표시 → 다른 주사위 호버 시 그 주사위로 전환 → 떼면 복귀 → [이동] 클릭 시 사라짐. 콘솔 에러 0.
  - Play 대조 2차(경계 사례) — **4건 전부 일치**: 방어도 4인 몬스터(`-5 · 방어도 -4`), 시약 타일을 밟고 들어가는 공격(촉매로 7 → 9), 지뢰를 밟고 지나가는 공격, 처치 예고(`-3 · 처치` → 실제로 쓰러짐).
  - 타일 피해 노트는 처음엔 타일의 원 수치(지뢰 5)를 적었는데 실제로는 방진에 깎여 4가 들어갔다 → `TileAttribute.ForecastDamage`(그 타일에 섰다고 치고 파이프라인 시뮬레이션)로 바꿨다. 보정이 없는 상황(지뢰 9 → 실제 9, 2건)은 다시 대조했고, 방진으로 깎이는 상황은 수정 후 다시 대조하지 못했다.
- Play로 확인하지 못한 것: 지뢰·치유·시약 외의 타일 노트(점액·꿀·불꽃·속박·빙결·자수정·뼈 방패·조화/부조화·활력 — 문구는 자가 테스트와 코드 대응으로만 확인), 회피 있는 대상 표시, 도착지 위험 줄이 실제 피격으로 이어지는지.

### 추가 (2026-10-04, 사용자 피드백)

- **체력바에 깎일 만큼 표시** — "체력 슬라이더에 예상만큼 표시해야 할 것 같다". 대상 몬스터 체력바의 채움 오른쪽 끝에서 예상 손실만큼이 밝은 크림색으로 깜빡인다 (`MonsterUI.SetForecastLoss`, 비율 계산은 순수 함수 `ForecastRange`). 구간은 채움(Fill)의 자식이라 채움 끝에 정확히 붙는다 — 처음엔 Fill Area 기준으로 놓았더니 채움이 여백만큼 삐져나왔고, 채움 스프라이트를 그대로 쓰면 붉은색에 곱해져 묻혔다(단색으로 변경). 예고가 사라지면 같이 사라진다. Play: 대상 3마리에 구간 3개, [이동] 클릭 후 0개, 실제 손실과 일치.
- **예고 카드 배경을 평평한 패널로** — "기본 패널 스프라이트에 창 제목 표시줄 같은 헤더가 있는데 그것 없이 평평한 패널을 써야 할 것 같다". 키워드 툴팁 프레임(`TooltipFrame`)에는 위쪽에 띠가 있어 카드 첫 줄이 띠에 걸렸다. 같은 그림에서 띠만 종이색으로 덮은 `battle_plain_panel.png`를 만들어 새 스킨 파트 `PlainPanel = 114`로 등록했다 (`Tools/make_plain_panel.py` — 외곽선·모서리·그림자·종이 결은 원본 그대로, 힉스필드 크레딧 사용 없음). 키워드 툴팁은 기존 프레임을 그대로 쓴다. UI 스킨 점검 이슈 0.
